Bully Co-op Hamdan | LAN Launcher v0.17 ALPHA
=============================================
مبني على مصدر v0.16b المشي المستقر من اختبار حمدان، من دون تعديل أي سطر في bridge/dinput8_proxy.cpp.
واجهة مستوحاة من أفكار VCCoop (Host, Join, Lobby, Ready, Ping, Start)؛ لا تنقل كود Vice City أو ملفاتها.

الموجود في الإصدار:
- برنامج Windows GUI حقيقي (C# WinForms / .NET Framework 4.x)، لا يحتاج Python.
- HOST يفتح غرفة TCP على Port+1، وGUEST ينضم عبر IPv4 ورمز غرفة 6 أرقام.
- Ready / Start: HOST يطلب بدء تشغيل اللعبة على الكمبيوترين بعد جاهزية GUEST.
- المود نفسه يتبادل المواقع على UDP Port عبر DLL v0.16b المستقرة (شبكة LAN/VPN)،
  واللانشر يبحث عن PEER VERIFIED في لوق اللعبة الجديدة لتمييز اتصال المحرك عن اتصال اللوبي.
- فحص Bully.exe بحجم النسخة المدعومة 8204288 بايت؛ والتحقق من DLL x86 وعلامة v0.16b.
- حفظ مسار اللعبة والاسم وخيارات الاتصال، ونسخة احتياطية من INI السابق قبل أول تشغيل.
- يحتفظ باللوق القديم بنقله إلى اسم مؤرشف. لا يقوم بتعديل Bully.exe.

الطريقة من نفس الكمبيوتر:
1) من GitHub Actions شغل "Build Bully Co-op HAMDAN LAN LAUNCHER v0.17".
2) نزّل Artifact وفك ZIP. حط dinput8.dll من الإصدار الجديد بجانب Bully.exe في
   Bully_HOST و Bully_GUEST (يجب أن تكون كل لعبة بنسخة مستقلة).
3) شغّل BullyCoopLauncher.exe مرتين؛ في نافذة HOST اختر مجلد Bully_HOST.
4) خل "تجربة نسختين على نفس الكمبيوتر" مفعلة، واضغط إنشاء غرفة HOST.
5) في نافذة GUEST اختر مجلد Bully_GUEST؛ اكتب رمز غرفة HOST نفسه،
   والعنوان 127.0.0.1 والمنفذ 7792، واضغط JOIN ثم READY.
6) في نافذة HOST اضغط START GAME. يُطلب تشغيل اللعبتين في مجلديهما.
7) داخل HOST اضغط F9 ثم F10، وحرّك Guest مسافة 5–10 وحدات وفي نفس الارتفاع.
   لا تختبر مطاردة بعيدة؛ v0.16b توقف المشي إذا الهدف أبعد من 24 وحدة.
8) راقب حالة "UDP GAME CONNECTED" في اللانشر ولوق اللعبة. انتظر تحميل المكان في كلا الطرفين.

الطريقة بين جهازين:
1) كل لاعب يحتاج نسخة Bully.exe المطابقة و DLL v0.16b. اختر "نفس الكمبيوتر" = OFF.
2) وصّل الجهازين على LAN واحدة أو شبكة VPN خاصة تثق بها. لا يوجد خادم مطابقة عام ولا تشفير.
3) عند HOST: اللعبة ستستقبل UDP Port (افتراضي 7792)، واللانشر TCP Port+1 (7793).
   اسمح للاتصالين في Windows Firewall على الشبكة الخاصة. لا يلزم فتح منفذ للـGUEST عادة.
4) HOST يعطي GUEST عنوان IPv4 الداخلي (ipconfig) ورمز الغرفة والمنفذ.
5) GUEST يدخل عنوان IPv4 والرمز، ثم JOIN وREADY؛ بعدها HOST يضغط START GAME.
6) إذا اللانشر قال "LOBBY CONNECTED" فقط فهذا لا يثبت دخول المود؛
   ابحث عن "UDP GAME CONNECTED" و PEER VERIFIED في اللوق.

مهم جدًا:
- المشروع حاليًا ليس تعاونيًا كاملًا! لا يوجد تحكم مباشر بجيمي الثاني ولا مزامنة
  المهمات، القتال، الـNPCs، الحوارات، الحفظ، المركبات، أو مشاهد القصة.
- LAN ليس خادمًا سحابيًا ولا يعبر NAT تلقائيًا. للإنترنت استخدم VPN خاصة أو إعدادات شبكية
  صحيحة، ولا تعرّض اللانشر ذي الرمز البسيط للإنترنت المفتوح.
- في اختبار نفس الكمبيوتر يبقى تحريك Host في الخلفية مغلقًا حفاظًا على الاستقرار.
- ملفات DLL قد تسبب انهيار اللعبة على نسخة Bully.exe أخرى؛ احتفظ بنسخ اختبارية مستقلة.
- لا تشارك أي ملف لعبة محمي؛ هذه الحزمة مصدر اللانشر وجسر DLL فقط، وليست اللعبة.
- اختبار بناء الكود على Windows يتم عبر GitHub Actions؛ لا نزعم أنه جُرّب داخل اللعبة.

الخطوة الجاية بعد نجاح اللوبي على جهازين: مزامنة الدوران/الجري/الوقوف أولًا بصورة
قراءة فقط من الـGUEST، ثم أوامر محرك اللعبة الآمنة للنموذج الثاني، تدريجيًا.
